把一个插件的两个参数接给 MediaPipe 手部追踪。**默认关闭**，用户在下拉菜单里
选择 `camera-left` / `camera-right` 才加载，选 `camera-off` 立即释放。

## 0. 映射规则（htmltry 版）

| 项 | 取值 |
|---|---|
| 手数 | `numHands: 2`（必须同时看到两只手，才能保证只跟目标手） |
| 手性锁定 | `camera-left` **只认左手**，`camera-right` **只认右手**；另一只手不产生控制量 |
| 关键点 | 食指指尖 `landmarks[8]` |
| 工作区 ROI | 画面 x / y 各 **20% ~ 80%**（中央 60%，四边各留 20%） |
| 外圈 20% | 手掌活动冗余，不参与控制；指尖拖出 ROI 时**钳制在边缘** |
| 输出 `x` | ROI 内归一化 0~1，**手往右 = 1** → `cutoff` |
| 输出 `y` | ROI 内归一化 0~1，**手往上 = 1** → `q` |
| `camera-left` | 系统首选摄像头 |
| `camera-right` | 优先第 2 个视频设备（stereo 另一机位）；只有一个时回退首选 |
| 显示 | 手控中心点插件**不画额外预览**：坐标直接合流进插件自己的中央 pad / 雷达。htmltry 仍保留 ROI 小画布 |

```js
latest = { present, x, y, hand, fps, seq }
//  present=false 时 x/y 保持上一次有效值(参数不弹回)
//  seq 每出一帧推理 +1,发送端用它判断"来了新样本"
```

> 上表的 `cutoff` / `q` 是 htmltry 的落点。本仓十二台手控中心点插件不经过它们:
> 手势 `x / y` 直接写 `x / y`(SwarmGrain 系为 `centerX / centerY`)。
> 映射层只负责把 0~1 平滑后送进通道,与具体参数名无关。

### 0.1 手性过滤（两个坑叠在一起）

**坑 1：必须开 `numHands: 2`。** 只想跟一只手时容易顺手设成 1，但那样模型只会
返回它认为最显著的那只手 —— 你想跟的手可能根本不在结果里，过滤就变成"永远没有手"。
开 2 之后按手性挑选，另一只丢掉。

**坑 2：手性是否需要对调，因机器而异，必须实测。** MediaPipe 的手性分类器是按
「输入已水平镜像（自拍）」训练的；输入是不是镜像，取决于宿主给的是原始帧还是镜像帧。
**本机实测不需要对调**（2026-11：报告的 Left/Right 与真实手一致，开关为 `false`）：

```js
const CFG = {
    NUM_HANDS: 2,
    HANDEDNESS_SWAP: false,   // 本机:报告即真实手性。反了才改成 true
    ...
};

const WANT_HAND = { 'camera-left': 'Left', 'camera-right': 'Right' };

export function pickHand(hands, cats, mode, swap = CFG.HANDEDNESS_SWAP) {
    const want = WANT_HAND[mode] || 'Left';
    for (let i = 0; i < hands.length; i++) {
        const raw = cats[i]?.[0]?.categoryName;
        if (resolveHanded(raw, swap) === want) return i;   // 找不到就 -1
    }
    return -1;
}
```

判定链：`handednesses[i][0].categoryName` →（`HANDEDNESS_SWAP` 对调）→ 与模式的目标手比较。
返回 `-1` 表示"目标手不在画面里"，此时 `latest.present = false`，参数保持上一次值。

`HANDEDNESS_SWAP` 是唯一需要按机器校准的开关，默认 `false`；**如果 left 模式
控住的是右手（或 right 控住左手），改成 `true`**。首次识别成功时控制台会打印一条，例如：

```text
[gesture] 手性: 报告 Right → 判定 Left;本模式只用 Left 手
```

### 0.2 方向定标（换机器会踩）

两轴的取反开关集中在 `ORIENT`，因为它跟**摄像头画面的朝向**绑定，不是逻辑的一部分：

```js
const ORIENT = {
    'camera-left':  { invertX: true, invertY: true },
    'camera-right': { invertX: true, invertY: true },
};
```

本机实测的结论：

- **原始 y 向下递增**（`y` 小 = 手在上方）→ `invertY: true` 才能「抬手 = q 升高」；
- **没有水平镜像**（手往右 → `rawX` 变小）→ `invertX: true` 才能「手往右 = cutoff 升高」。

判断方法：某轴手感反了就翻对应的一项，另一轴不用动。
本仓十二台手控中心点插件没有 ROI 预览画布，所以不提供 Shift/Alt 点击定标，
改 `ORIENT` 后重新加载界面即可（htmltry 仍支持 Shift/Alt 点击定标）。

映射细节：

```js
const ROI_LO = 0.20, ROI_HI = 0.80;   // 中央 60%，四边各留 20%
const ROI_SPAN = ROI_HI - ROI_LO;

const rx = clamp01((tip.x - ROI_LO) / ROI_SPAN);
const ry = clamp01((tip.y - ROI_LO) / ROI_SPAN);

latest.x = orient.invertX ? 1 - rx : rx;   // 钳制后再取反，仍在 0~1
latest.y = orient.invertY ? 1 - ry : ry;
```

### 0.3 分工：拾取只做一帧，重活在发送端

MediaPipe 的指尖坐标在静止时有 ±0.5%~1% 的逐帧抖动。**重滤波不要放在拾取层**——
那一层要做的是"尽快反映手的位置"，多级滤波会让手感发黏。

所以分两段：

| 段 | 位置 | 做什么 |
|---|---|---|
| 拾取 | `gesture.js` | **只做一帧单极点低通**，抹掉单帧尖刺，延迟恒定 1 帧 |
| 发送 | `index.html` 60fps | 自适应滤波 + 帧级插值，承担主要的抖动抑制 |

`gesture.js` 交付：

```js
latest = { present, x, y, hand, fps, seq }
//  x / y 已过一帧低通(CFG.SMOOTH),不是裸值
//  seq 每出一帧推理 +1,UI 用它判断"来了新样本"
```

一帧低通就是这么一行：

```js
const CFG = { SMOOTH: 0.5, ... };   // 1 = 关闭；0.25 ≈ 3 帧；0.5 ≈ 1 帧

export function smoothPick(raw, key, a = CFG.SMOOTH, st = pickSmooth) {
    if (a >= 1) { st[key] = raw; return raw; }
    st[key] += (raw - st[key]) * a;
    return st[key];
}
```

**为什么 0.5 就是"一帧"**：单极点的平均延迟 = `(1 - a) / a` 帧，
`a = 0.5` → 1 帧（15fps 下 67ms）。实测 ±0.4% ROI 交替抖动，拾取端摆幅
从 0.80% 降到 **0.267%**（衰减因子 `a / (2 - a) = 1/3`，与理论一致）；
0.15 ROI 的阶跃 4 个样本（≈250ms）进入 1% 误差。

**重新捕获要直接对齐**，否则手丢掉再回来会从旧位置滑过去：

```js
if (!wasPresent) { pickSmooth.x = p.x; pickSmooth.y = p.y; }
wasPresent = true;
```

`hardRelease()` 与 `start()` 里都会把 `wasPresent` 清掉并让 `pickSmooth` 跟上
当前输出，所以切摄像头、切轨道都不会带旧状态。

发送端（`index.html`）两级：

| 级 | 频率 | 做法 |
|---|---|---|
| ① 样本级 | 15fps（`seq` 变化时） | 按偏差**方向是否持续**选增益：抖动会不断变号走慢通道，真移动方向不变立刻提速 |
| ② 帧级 | 60fps | 向 ① 的结果插值（`TAU_I`），把 15fps 的台阶抹成连续运动 |

```js
const GST = {
    A_SLOW: 0.16,   // 抖动通道:慢
    A_STEADY: 0.55, // 连续同向(真移动):快
    A_FAST: 0.80,   // 大幅偏差:更快
    NOISE: 0.022,   // 死区:偏差在此以内不额外加速
    SPAN: 0.030,    // 超出死区后再走 3% ROI 升到 A_FAST
    SNAP: 0.12,     // 单样本跳变 >12% ROI 直接跟上
    TAU_I: 0.05,    // s,帧级插值时间常数
};
```

**关键判据是"偏差方向是否持续"**，不是偏差大小：

```js
// st 是每轴的状态:{ v: 滤波值, sg: 上次偏差方向, n: 同向连续样本数 }
const d = raw - st.v;
const sg = Math.sign(d);

if (sg === st.sg) st.n++;
else { st.sg = sg; st.n = 1; }

const gain = Math.min(1, Math.max(0, Math.abs(d) - GST.NOISE) / GST.SPAN);
const a = st.n >= 2
    ? Math.max(GST.A_STEADY, GST.A_SLOW + (GST.A_FAST - GST.A_SLOW) * gain)
    : GST.A_SLOW + (GST.A_FAST - GST.A_SLOW) * gain;

st.v += d * a;
```

抖动每帧变号（`n` 恒为 1）→ 永远走慢通道；手朝一个方向移动（`n` 累积）→ 立刻提速。
只看大小分不出来：±1% 的抖动和 ±1% 的真实移动，偏差大小完全一样。

这条判据是试出来的。最早按"偏差大小"分级（小 = 慢、大 = 快，阈值 3.5%），
结果 ±2% 的抖动在阈值附近反复换挡，`cutoff` 摆幅反而被放大到 **9.24%**；
改成方向持续性 + 死区后，同样是 ±2% 抖动，摆幅降到 **1.32%**，±1% 降到 **0.54%**
（都是部署目录里拦截 `sendControlData` 实测，不是仿真）。

实测（部署目录里跑真实 tick 循环，拦截 `sendControlData`）：

| 场景 | 结果 |
|---|---|
| 静止手 + ROI ±1% 抖动 | `cutoff` 摆幅 **0.54%**（原始直通是 10.8%） |
| 同上，叠加拾取端一帧低通后（±0.4%） | 4 秒内 `cutoff` **只发 1 次**，摆幅 0 |
| 静止手 + ROI ±2% 抖动 | 1.32% |
| 手完全静止 | **0 次发送** |
| 阶跃 14% ROI | t90 137ms / t99 254ms |
| 阶跃 6% ROI | t90 214ms / t99 417ms |
| 阶跃 2% ROI | t90 319ms / t99 533ms |

调参：**还抖就调小 `A_SLOW`**，**觉得钝就调大 `A_STEADY`**；`NOISE` 是抖动/移动的
分界带，手抖更大就把 `NOISE` 提到抖动峰值之上（单位：ROI 归一化，0.022 ≈ 2.2%）。

## 1. 为什么必须做生命周期管理（实测驱动）

在 Ableton Live 里切走插件界面后会出现**最坏组合：付费但功能为零**：

| 现象 | 原因 |
|---|---|
| 手势失效 | rAF 停摆 → 不推理 |
| 摄像头灯仍亮 | `MediaStreamTrack` 不依赖 rAF，继续以 30fps 采集 |

实测（2026-10，htmltry.au）：隐藏 47.1 秒内 rAF **48/48 采样全停滞**、推理归零，
但视频帧仍送来 **1383 帧（29.4fps）**。纯浪费。

关键结论：**采集层和计算层是两套调度**，只停 rAF 不会停摄像头。

## 2. 状态机

```
                  start()              hidden
   off ──────────────► starting ──► running ────► suspended
    ▲                     │            ▲              │
    │ stop()              │ 失败        │ visible      │
    └─────────────────────┴────────────┴──────────────┘
```

- `suspended` 必须 **`track.stop()` + `landmarker.close()`**（灭灯 + 释放 WebGL/模型）
- 恢复时**重建**，不能复用已 close 的 landmarker
- **用户没点过关闭，就不该被关闭** → `desired` 标志独立于可见性

## 3. 双防线

```js
// 主防线：visibilitychange 在 Live 里实测可靠，响应即时
document.addEventListener('visibilitychange', () => {
    if (document.hidden) {
        if (state === 'running' || state === 'starting') suspend('visibilitychange');
    } else if (state === 'suspended' && desired) {
        resume('visibilitychange');
    }
});

// 兜底：某些宿主不派发事件，但 rAF 一定会停
setInterval(() => {
    const stall = performance.now() - lastSentinel;
    if (stall > 2000) armSentinel();            // 自愈，见 §4 ②
    if (stall > 2000 && state === 'running') suspend('watchdog');
    else if (state === 'suspended' && desired && stall < 500) resume('watchdog');
}, 700);
```

⚠️ 看门狗里**不要**用 `!document.hidden` 做前置条件。实测存在
"`document.hidden === true` 但没派发 `visibilitychange`" 的宿主，
加了这个条件会漏掉挂起，摄像头永远不关。

## 4. 四个必须避开的坑（全部实测踩过）

**① `await video.play()` 会永久挂起**

复用 video 元素重新挂 `srcObject` 时，`play()` 可能永不 settle，
状态机卡死在 `starting`。必须加超时竞速：

```js
await Promise.race([v.play(), new Promise(r => setTimeout(r, 1500))]);
```

**② 哨兵 rAF 不能靠"ID 非零"判断存活**

rAF 被宿主打断后回调不再排队，但 `sentinelId` 残留非零值 →
之后永远重建不了 → 恢复后检测不到"已可见"，自动恢复失效。

改用代际令牌，可无条件重建：

```js
let sentinelGen = 0;
function armSentinel() {
    const my = ++sentinelGen;
    const loop = () => {
        if (my !== sentinelGen) return;
        lastSentinel = performance.now();
        requestAnimationFrame(loop);
    };
    requestAnimationFrame(loop);
}
```

隐藏期间只是空排一帧，无害；但不重建就再也活不过来。

**③ generation token 防竞态**

`suspend()` 时可能有 `detectForVideo()` 在途，撞上已 close 的 landmarker 会抛异常。
每次 acquire/release 都 `gen++`，异步回调里逐段检查 `if (myGen !== gen) return;`。

UI 侧同理：启动 `gesture.js` 是异步的（模型 + 授权可能数秒），
若期间用户又改了下拉菜单，旧启动必须作废并 `stop()`，不能把摄像头留在运行态。

**④ 事件监听只装一次**

`stop()` 会清定时器，但不该重复叠 `visibilitychange` 监听器。用 `guardsInstalled` 标志。

## 5. 性能参数（性能优先）

```js
const CFG = {
    INFER_FPS: 15,        // 控制量靠 60fps 插值补顺，15fps 够用
    NUM_HANDS: 2,         // 手性过滤要求同时看到两只手；成本约 1.5~2 倍
    CAPTURE: { width: 640, height: 480, frameRate: { ideal: 30 } },
    HANDEDNESS_SWAP: false,
    SMOOTH: 0.5,          // 拾取端一帧低通；1 = 关闭，0.25 ≈ 3 帧
    WATCHDOG_MS: 2000,    // rAF 停滞多久判定为隐藏
    WATCHDOG_POLL_MS: 700,// 看门狗轮询间隔
};
```

实测参考（M2）：GPU 建图 140ms、单帧推理 4–6ms、GPU delegate 25–40fps、
**CPU delegate 建图约 27 秒（陷阱，只能兜底）**、端到端延迟 60–90ms。

**成本结论**：未选摄像头时开销精确为 0（模块都没 import）；
一次只有一个可见窗口在推理；隐藏即释放。
所以**手势对"8 轨道同时运行"的预算影响 ≈ 0**，真正吃 CPU 的是 DSP。

## 6. 分发

`mediapipe/` 有 16.8MB。**十二台插件（Boids / Stasis / SwarmGrain × Quad / Depth / HRTF / Ambi）
都要用**，但**仓库里只存一份**：`shared/gesture/`。需要时用脚本复制：

```bash
python3 scripts/gesture-assets.py          # 复制到 12 个带 gesture.js 的工程
python3 scripts/gesture-assets.py --check  # 检查
python3 scripts/gesture-assets.py --clean  # 删除副本
```

复制出来的 `mediapipe/` 已在 `.gitignore` 里排除（12 份 = 200MB，不进仓库）。
**导出前必须先跑这一步**：`export_plugin.py` 是「源目录整份同步」，
源目录没有 `mediapipe/`，运行时目录也不会有，宿主里只是「CAMERA 失效」，不报错。

`quad Doppler/tools/export_plugin.py` 的运行时部署是**源目录整份同步**（跳过 `build/`），
所以 `gesture.js` / `gesture-ui.js` / `mediapipe/` 跟着导出自动走，不用手工拷。

> ⚠️ 别只往 `~/Library/CabbageAudio/<插件名>/` 里手工放：脚本重建运行时目录时会先
> `rmtree`，手放的文件在**下一次导出**就没了（宿主里只是「CAMERA 按钮不见了」，无报错）。
> 曾经因为「改图标 → 重新导出」，多台的手册和手势文件被一起删掉过。

确有需要共享同一份模型时，也可以在运行时目录里做软链（导出会重建目录，所以软链要
放在**源工程目录**里或用下面的形式补回来）：

```bash
ln -s ../../../<共享目录>/mediapipe ~/Library/CabbageAudio/<插件名>/mediapipe
```

## 7. 接入步骤

1. 把 `gesture.js` 与 `gesture-ui.js` 放进**源工程目录**（导出时自动同步进运行时）
2. `mediapipe/` 放到源工程目录（跑 `python3 scripts/gesture-assets.py` 自动复制）
3. 在 `index.html` 的模块脚本末尾接一行：
   ```js
   import('./gesture-ui.js').then(({ attachGestureControl }) => {
       attachGestureControl({
           channels: { x: 'x', y: 'y' },        // SwarmGrain 系改成 centerX / centerY
           read: () => ({ x: X, y: Y }),        // 当前 UI 值,起步不跳变
           write: (x, y) => { X = x; Y = y; placeBall(); },
           send: (id, v, g) => Cabbage.sendControlData({ channel: id, value: v, gesture: g }, null),
           blocked: () => dragOn.pad,           // 手动拖拽时让位（见下方注）
       });
   }).catch(e => console.warn('Cabbage: 手势模块不可用 —', e));
   ```
   > **`blocked()` 必须覆盖该台的所有拖拽态**，不能照抄成 `dragOn.pad`。
   > 十二台实测各不相同：
   > `Object.values(dragOn).some(Boolean)`（Boids 系）、
   > `dragOn.radar || anyDrag()`（Stasis 系）、
   > `padActive || anyDrag()`（Quad-Stasis）、
   > `Object.values(dragOn).some(Boolean) || padDrag !== null`（SwarmGrain 系）。
   > 少覆盖一个状态，手势和鼠标就会同时改同一个参数。
   `gesture-ui.js` 只负责下拉口、生命周期与 §0.3 的两级平滑，**不新增任何预览浮层**；
   `gesture.js` 只做拾取 + 一帧低通（`CFG.SMOOTH`）。
4. 在 60fps 循环里读 `gesture.latest`（已封装在 `gesture-ui.js`）：
   - `L.seq !== gSeq` 才算新样本，才是更新目标的时机
   - 手在画面中才更新目标，离开时保持上一次值
   - 用 §0.3 的两级滤波平滑后 `sendControlData`
